# 阶段 3、4、5 加固计划

本计划承接阶段 0、1、2 的本地实现，仍不推送、不部署、不访问线上数据库。

## 阶段 3：契约与回归阻塞清理

- 将旧 TacticalCollaboration 测试迁移到已确认的权限契约：斥候只能创建/修订自己的 `system_count`；具名舰队、舰船明细和舰队修订由统帅/指挥执行。
- 保留越权 403、可见性和版本冲突测试，不能通过放宽生产权限来让旧测试变绿。
- 将命令结果中的 `state_version` 纳入所有成功响应断言。
- 验收：`TacticalCollaboration.tests` 全绿，旧测试不再测试已废弃的斥候舰队权限。

## 阶段 4：前端加载与交互性能

- 所有重量级页面改为路由级懒加载；战术板、军团、星海见闻、行星计算器、星图导航和管理页面不得进入首屏主包。
- 对图表、动画和图标依赖设置稳定 vendor chunk，避免单个入口超过预算。
- 继续保留战术板移动端“不下载星图”的边界、地图视口分层和列表分页。
- 验收：生产构建成功，主入口和最大异步 chunk 均在明确预算内，既有前端单测和关键 Playwright 回归保持通过。

## 阶段 5：发布前可靠性门禁

- 为本地负载脚本增加明确的输出指标与失败退出码，区分“本地 SQLite 通过”和“真实 MySQL 尚未验证”。
- 增加发布前静态检查：迁移漂移、前端预算、危险生产目标和未处理构建失败必须阻断。
- 更新文档，明确真实 MySQL 并发、ASGI/代理/TLS、备份恢复仍需隔离环境验收；不把本地演习结果包装为生产容量结论。
- 验收：阻塞项可复现、失败可定位、不会误连线上服务。

## 非目标

- 不改变当前已确认的斥候权限模型。
- 不在本阶段开发装配模拟器或完整舰船图鉴。
- 不执行生产迁移、推送、合并或上线。
