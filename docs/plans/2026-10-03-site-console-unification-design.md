# 深色控制台视觉统一与制造页加载优化设计

## 目标

将市场、制造、战术板、战报和通用页面统一到同一套深色 EVE 控制台设计系统，修复制造目标切换后舰船图片延迟出现的问题，并提升桌面端与窄屏端的排版稳定性。

## 已确认的问题

- 制造页样式文件存在多段历史覆盖，页面头部、标题字号、面板边界和侧栏间距并不共享同一套 token。
- `GameItemImage` 默认对所有图片使用 `loading="lazy"`。制造树使用独立滚动容器，切换目标后首层图片请求可能被浏览器延迟，截图中的深色方块是未完成的图片状态。
- 资源本身已齐全，不需要更换图标来源；应在组件层增加加载优先级，而不是复制或内嵌素材。

## 设计决策

采用推荐的“深海军蓝 + 琥珀操作色 + 青灰信息色”控制台方案：

1. 以全局 `--console-*` token 作为唯一基础色、边框、阴影、圆角和间距来源；制造页不再自建互相冲突的浅色 token。
2. 页面统一为“标题区 → 工具/状态区 → 主内容区”的垂直节奏，标题不超过两级，左上角 eyebrow 使用同一字号、字距和颜色。
3. 桌面端使用固定内容宽度与 24px 主边距，侧栏宽度由 shell token 控制；制造页三栏采用同一栅格 gap，不再使用 1px 拼接边框造成拥挤。
4. 面板和按钮使用轻微层级差、细边框、短时 hover/press 过渡；不引入持续动画或大面积发光，保证信息密度和可读性。
5. 制造页目标图标和展开后首层节点使用 `priority`/`eager` 加载；弹窗选项和深层节点保留 lazy。切换目标时先显示稳定的骨架/占位，避免布局跳动。
6. 小屏幕把三栏堆叠成“目标与参数 → 制造树 → 成本摘要”，保留 16px 页面边距、44px 触控目标和可滚动内容，不压缩正文到不可读的字号。

## 非目标

- 不更换客户端素材、不修改制造配方和成本计算逻辑。
- 不改变登录、API、WebSocket 或生产权限策略。
- 不把所有全站图片改成 eager，避免首屏网络和内存开销扩大。

## 验收标准

- 制造目标切换后，目标图标和首层制造节点不再出现长时间的空黑占位；组件测试能证明优先级向 `<img>` 传递。
- 制造页、市场页和通用页面的标题、面板、按钮和侧栏边距使用同一套 token；视觉回归截图不出现浅色残留或错位。
- 1280px 以上桌面端主内容左右留白均衡；760px 以下页面不出现横向滚动，所有主要操作目标至少 44px。
- 前端单元、预览契约、制造相关 e2e 和构建预算全部通过。
