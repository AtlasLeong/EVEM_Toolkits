# 多板战术组织与海盗情报板设计

日期：2026-09-24
状态：用户已确认本地第一版；不包含推送或线上部署。

## 目标与边界

- 每个用户最多**创建**三个组织；加入其他组织不计入创建额度，也不限制加入数量。
- 每个组织最多三块板，可以是任意战争沙盘板 / 海盗情报板组合。成员、统帅、指挥、斥候及邀请审批属于组织；内容与星图范围属于板。
- 现有每个组织自动拥有一块承载原有范围、部署及上报的战争沙盘板；原链接未指定板时继续进入它。
- 海盗情报以“游戏角色名 + 精确船型”识别目标。一次目击是一条独立记录，不并入战争板的人数或舰队统计。星系精度和星座精度明确区分；后者不得伪装成某颗星系的精确坐标。
- 海盗情报板斥候只可读取、搜索、汇总和撤下自己的记录；统帅/指挥可见全板。权限必须在服务端查询投影前生效，不能靠前端隐藏。

## 模型与兼容

新增 `Board`，保存组织、类型、名称、独立星域范围与范围版本；每块板有稳定 ID。`Organization` 继续承担成员、邀请、在线名额及组织级权限版本。创建组织时可选首块板类型，旧请求缺省战争板。`list_organizations` 对活跃成员返回其板列表；待审批者不接收板细节。单独的板创建接口只允许统帅/指挥，受三块上限约束，按请求 UUID 幂等。

`Report` 与 `Force` 增加 `board` 外键，并在迁移中把旧内容归到自动创建的默认战争板。现有组织级路径保留为兼容入口；没有 `board_id` 时只选择该组织**固定的默认战争板**，不会在后来新建战争板时悄悄改指向。以海盗板起步的组织没有默认战争板，旧路径返回不存在；新客户端总是传明确板 ID。所有新战争写入均绑定板，跨板 `report_id`/`force_id`/关联部署一律视为不存在。旧 `Organization` 范围列保留到下一次兼容清理；默认旧战争板同步其范围，以免旧客户端或既有测试读到不同战区。

新增 `PirateSighting`，包含所属板、上报者、显示角色名/船型及 NFKC+大小写折叠检索键、地点类型与 ID、观测时间、可选每日 UTC 活跃时段、备注、状态和版本。星系或星座只能二选一，写入时验证静态宇宙表。相同角色与船型的多次目击在**可见记录集合内**按最新观测时间聚合成目标；原始目击始终保留。超过 48 小时的目击以历史线索呈现，不称为实时位置。撤下采用状态更新和版本校验，不物理删除。

## API 与同步

- 保留 `/api/tactical/organizations/`、邀请和成员接口；创建组织接受可选 `board_type`。板目录与新建使用组织下的 `boards/`。
- 战争板的 snapshot、map、commands、WS 鉴权帧接收板 ID；省略时走旧战争板兼容入口。在线租约及 100 账号容量仍按组织计，战术命令仍要求有效租约。
- 海盗板使用独立快照与命令接口，快照先检查活跃成员再作斥候 `author_id` 过滤；服务端计算可见目标总数，客户端仅在已过滤的可见记录中聚合、搜索和生成地图标记。写入使用现有请求 UUID 收据及组织行锁，但不发布含全板人数/版本的斥候可见事件。第一版最多保存 5000 条目击，快照含完整可见历史；扩大规模前再做增量同步/分页。
- 第一版海盗同步采用页面可见时的低频 HTTP 更新及提交后的立即刷新；暂不接入向全组织广播的战争 WebSocket，以免其他斥候的上报时机泄漏。失焦停止周期刷新，失败按 15/30/60 秒退避，请求设超时，手动刷新可用。组织板目录在重新聚焦及可见页低频刷新，以发现他人新增的板。
- 静态星图目录补星座搜索；星图几何仅含公开宇宙数据，不缓存成员或情报。

## 页面

“创建组织”表单先选两张图标加文字的可键盘操作卡片：`Crosshair`「战争沙盘板 · 敌我兵力与战区协同」和 `Radar`「海盗情报板 · 目标活动与伏击线索」。重试签名包含类型，防止切换类型沿用旧 UUID。进入组织后用板切换器显示最多三块板，并允许统帅/指挥增建；同类型板以名称区分。

战争板延续现有页面。海盗板独立页面：左侧可搜索的目标列表和上报入口，右侧只显示真实星图与简洁定位标记；选中目标后显示角色名、船型、最后观测、地点精度、上报者及历史。星座级线索在星座层级呈现，不落到单颗星系。斥候看到的列表/地图/计数均来自服务端自己的投影。手机端先展示列表、搜索和上报，地图作为可展开的第二视图；避免密集浮动卡与持续动画。控件对比度和触控尺寸沿用现有战术板改进后的标准。

## 验证与发布范围

先用失败测试覆盖创建额度、三板上限、旧数据归属、同类板隔离、跨板写入拒绝、权限矩阵、目标归一化、星座/星系精度、撤下和幂等。再跑全部战术后端测试、前端单测/构建、桌面与手机浏览器流程。仅交付本地可测版本；未经用户另行要求不推送、不部署。
