# 战术星图缩放与密度优化设计

## 背景

战争沙盘板与海盗情报板目前各自维护缩放预览逻辑。滚轮预览时，星点、选中环、命中区域、标签和卡片并不共享同一份实时相机：世界层已经移动/缩放，但尺寸敏感的 SVG 属性仍使用提交前的相机值，导致选中环瞬间变大、卡片尺寸跳变、松手后又回弹。高密度地图还会在每一帧参与过多 DOM 计算，标签淡入淡出会放大视觉抖动。

## 目标

- 两类战术板使用同一套滚轮归一化、帧合并和缩放边界规则。
- 预览期间位置连续，星点/选中环/命中区域/卡片保持可读的屏幕尺寸，不出现巨环、卡片变形或松手回弹。
- 只渲染视口附近的静态几何与标签，保留选中星系、目标标记和当前卡片，即使它们暂时位于视口边缘也不丢失。
- 缩放过程中不触发整张地图的标签淡入淡出；仅对真正新增的标签做一次短暂的稳定过渡。
- 保持现有数据模型、权限、上报、搜索和卡片归档行为不变。

## 方案

采用“统一实时相机 + 固定尺寸交互层”的增量方案，不重写为 Canvas/WebGL，也不在每个滚轮事件中触发 React 全量渲染：

1. 抽出共享的滚轮增量归一化、相机限制和 rAF 合帧工具。两张 SVG 战术板用同一套输入处理，触控板、鼠标滚轮和不同 deltaMode 的行为一致。
2. 将世界拓扑（星门、普通星点）与交互/标注层分离。预览只对世界拓扑做仿射变换；交互层使用实时相机计算屏幕位置，尺寸通过逆缩放或固定 CSS/SVG 几何保持稳定。对数量受控的标记、卡片和命中区域在 rAF 内更新，避免 React 重渲染。
3. 为静态星点和连线增加视口裁剪与稳定的标签 LOD；保留选中、报告和搜索命中的节点。通过标签数量上限和滞后阈值避免边界抖动。
4. 移除缩放结束时对整层标签的统一 reveal；只在节点真正从隐藏变为可见时添加一次短过渡，缩放中保持现有标签稳定。
5. 用浏览器回归覆盖预览态与提交态：选中环/命中区域尺寸、卡片尺寸、连续滚轮单帧增量、视口裁剪、标签稳定性；再跑密集星图性能、现有单元测试和构建。

## 验收标准

- 在 5,000 星点、5,950 星门的密集地图上连续滚轮 30 次，预览中选中环和卡片不出现数量级放大或缩小，松手后无回弹。
- 同一目标在两类战术板的卡片宽高与关闭控件样式一致，滚轮过程中宽高变化不超过 1px。
- 普通星点/连线只保留视口附近元素；选中、报告、搜索命中节点始终可交互。
- 原有上报、搜索定位、范围调整、舰队归档、成员权限和登录流程的测试全部通过。
- 生产构建成功，浏览器回归无新增错误；性能采样记录在提交说明中。

## 非目标

- 不更改星系数据、安等颜色、组织/房间权限和服务端接口。
- 不在本轮引入新的图形渲染依赖或部署配置。
