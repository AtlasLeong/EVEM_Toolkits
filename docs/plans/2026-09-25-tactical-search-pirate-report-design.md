# 战术星系搜索与海盗星系上报设计

## 目标

让战争沙盘可以在当前战区内搜索并定位真实星系；让海盗情报板可以直接点击真实星系节点打开目标线索上报表单，并自动预填地点，同时保留现有角色名、船型、观测时间和权限校验。

## 已确认的范围

- 战争沙盘搜索只覆盖当前板已加载的战区星系，不查询或虚构范围外星系。
- 搜索入口固定在地图左上方，提供键盘和鼠标可用的结果列表。
- 选中搜索结果后平滑聚焦星系、选中星系并短暂高亮；地图拖拽和缩放行为不改变。
- 海盗板继续使用真实星图，不新增假星系或独立布局。
- 点击海盗板星系的可见点、名称或透明命中区打开现有“上报目标线索”表单；星系 ID 和显示名作为初始地点。
- 上报仍需填写目标角色名、精确船型、观测时间；点击星系不会自动提交空白线索。
- 海盗板已有目标卡和目标标记的点击语义不变：它们继续打开目标详情/选择目标，而不是误触发新上报。
- 现有斥候可见性、服务端权限、地点精度和请求幂等逻辑不变。

## 方案与取舍

采用“地图内联上报”方案：复用现有 `PirateSightingForm`，把地图选中的系统作为 `initialLocation` 传入。相比增加详情卡少一步操作；相比直接创建空白记录，避免产生无法辨认目标的半成品数据。

战争搜索复用现有 `systemQuery` / `focusSystem` 状态和 `CollaborationMap` 的聚焦机制，仅提升入口可发现性、结果状态和定位反馈，不引入全宇宙目录请求。

## 组件与数据流

### 战争沙盘

1. `BoardContent` 从 `mapData.systems` 派生搜索结果，按中文名、英文名和系统 ID 做不区分大小写的匹配。
2. 地图搜索控件展示结果数量、安等和“当前范围”标识；无匹配时展示明确空状态。
3. 选择结果调用现有 `chooseSystem`，并通过带 token 的 `focusSystem` 交给 `CollaborationMap`。
4. `CollaborationMap` 将聚焦系统保持在安全可视区域，使用已有选中环和 `focusSystem` 高亮，不改变真实世界坐标。

### 海盗情报板

1. `PirateIntelMap` 接收 `onSelectSystem` 回调。
2. 真实星系节点由共享 `BoardStarGlyph` 绘制，增加独立的透明命中圆和键盘语义；星系标签也成为同一系统的可访问激活目标。
3. 回调携带完整系统节点（ID、名称、安等等），`PirateIntelBoard` 保存 `reportLocation` 并打开表单。
4. `PirateSightingForm` 接收 `initialLocation`，初始地点精度固定为星系；地点选择器仍可清除、改为星座或重新搜索。
5. 表单提交继续通过 `sightingPayload` 和 `sighting.create`，服务端仍是最终校验者。

## 交互与错误处理

- 搜索输入支持 Escape 清空结果，结果列表支持 Enter/Space 激活；点击地图空白不关闭已选系统。
- 地图范围为空时搜索控件不显示假结果，并提示先设置范围。
- 海盗板无星图数据、范围外或加载失败时不生成上报地点；用户可继续使用顶部手动上报入口和地点搜索。
- 星系点击与拖拽分离：只有指针移动未超过点击阈值时才激活，避免拖图误开表单。
- 表单关闭后清除本次预选地点；提交失败保留表单内容和预选地点，便于重试。
- 所有新按钮和命中区提供 `aria-label`、焦点样式和键盘等价操作。
