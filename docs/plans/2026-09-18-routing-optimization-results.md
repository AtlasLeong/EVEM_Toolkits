# 寻路优化验证结果

2026-09-19，`codex/routing-optimization` 独立分支。结果只代表本地合成数据，不代表线上 SLA，也没有连接生产数据库或服务器。

## 正确性

- `TacticalBoard` 隔离测试：24/24 通过。
- 随机对照包含 256 个固定种子的小图，使用独立 Bellman-Ford 规则实现验证累计成本和跳数；通过。
- 额外覆盖：同优先级节点、零成本星门、超射程星门诱导、负安状态分裂、严格 9 光年边界、严格射程边界、允许节点集合、旧版仅土路入口、索引与全扫描集合一致、快照并发刷新与错误响应。
- 全后端回归和部署测试在最终复核时重新执行；未修改数据库结构或生产配置。

## 本地合成基准

命令：

```text
python -B scripts/benchmark_routing.py
```

环境：Python 3.11.9、NumPy 2.4.6、SciPy 1.15.3（CI 仍固定 NumPy 1.24.3、SciPy 1.10.1）。6,000 个随机三维星系、256 个半径 5 光年查询，5 次取中位数；完整路线样本为 400 个相邻星系、半径 1.01 光年。

```text
indexed_build_ms=3.524
indexed_neighbor_batch_ms=1.708
full_scan_neighbor_batch_ms=628.381
neighbor_speedup=367.82x
indexed_line_route_ms=3.924
full_scan_line_route_ms=54.947
route_speedup=14.00x
```

索引和全扫描在基准中先做集合/路线一致性断言；索引查询使用保守半径并以原始距离再次严格过滤。实际速度会随机器、星系密度、半径和 SciPy 版本变化。

## 运行限制和运维说明

- 快照是每个 worker 自己维护的 300 秒 TTL；批量导入星图后仍建议受控重启全部 worker 立即刷新。
- 同一安全模式的刷新单飞，不同安全模式可以并行；刷新期间不会持有全局状态锁。刷新失败返回 503，并有 5 秒退避，不会把故障伪装成“无路径”。
- 新八限制仍保持原语义，仅限制端点，不新增中间节点策略。
- 外部多表导入过程没有数据库版本号或事务快照，无法声称导入期间跨表完全一致；这是本轮明确保留的边界。
