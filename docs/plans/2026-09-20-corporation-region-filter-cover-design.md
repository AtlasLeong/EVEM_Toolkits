# 军团星域筛选与顶部封面优化设计

## 目标

让军团详情页顶部封面更紧凑，同时让访客可以按活动星域筛选公开军团。

## 已确认范围

- 只压缩详情页顶部封面，不调整列表卡片封面高度。
- 桌面顶部封面目标高度约 160px，手机端约 128px；Logo 继续保持覆盖封面的视觉关系。
- 军团大厅增加“活动星域”下拉筛选，与现有活动方向筛选可组合。
- 筛选使用现有星域目录接口的标准中文名称，提交为 `region` 查询参数。
- 后端按已发布版本 `Revision.content.base_region` 做大小写无关的模糊匹配，兼容历史自由文本，不新增数据库字段或迁移。
- 筛选条件变化后重置到第 1 页；清空星域即可恢复全部公开军团。

## 方案与取舍

推荐直接复用现有星域目录和 `base_region` 文本：改动面小，旧资料无需迁移，也能保证服务端分页结果正确。新增独立 `region_id` 字段虽然更严格，但会引入迁移、旧数据补齐和编辑流程变更，超出本次需求。仅在前端当前页过滤会破坏分页准确性，因此不采用。

## 数据流

1. 军团大厅通过现有 `/api/regions` 加载星域选项。
2. 访客选择星域或活动方向时，更新 React Query key，并将 `region`、`activity` 和搜索词传给 `/api/community/corporations/`。
3. 后端校验星域参数长度，使用已发布 revision 的 `content.base_region` 过滤，继续应用公开、已审核和分页约束。
4. 详情页只调整封面容器 CSS；图片仍由既有安全图片组件和 `object-fit: cover` 处理。

## 错误与兼容

- 星域目录加载失败时，筛选控件显示可理解的失败提示或保持禁用，不影响军团大厅搜索和其他筛选。
- 空星域参数表示不过滤；旧 revision 没有 `base_region` 时自然不匹配具体星域，但仍可通过搜索和活动方向找到。
- 保持已有 `q`、`activity` 参数和响应结构不变。
- 不修改生产数据、不新增迁移。

## 验收与测试

- 后端测试覆盖：有效星域匹配、与活动方向组合、无匹配结果、超长参数拒绝、空参数保持全量。
- 前端 E2E 覆盖：星域下拉出现、选择后发送正确查询并显示结果、清空恢复、桌面筛选控件对齐、详情顶部封面高度和手机端无横向溢出。
- 完整前端构建、海报单元测试、后端 Community 回归和全量 E2E 继续通过。
