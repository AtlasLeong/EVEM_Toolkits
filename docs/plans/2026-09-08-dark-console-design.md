# EVEMToolkit 全站深空控制台设计

## 已选择的视觉方向

用户在三张图中明确倾向第 2 张。以 [深空控制台参考图](../design/dark-console-reference.png) 为视觉目标，不擅自混入第 3 张的绿色或双栏筛选结构。

范围是现有 front-codex 全部页面，而非单独修改“加入计算器”按钮。当前步骤仅制定方案，业务代码和线上站点尚未修改。

参考规则：[taste-skill 的 redesign-existing-projects](https://github.com/Leonxlnx/taste-skill/blob/ccbc15639c97057cbfcf32ecebc38ef716e4bb37/skills/redesign-skill/SKILL.md)。该规则已读取，用于现有技术栈中的有针对性重设计；未安装或执行仓库中的第三方脚本。

## 视觉系统

- 深色基底 `#0b1117`，导航 `#0d141b`，内容表面 `#131c24`，抬升层 `#1a2631`，分隔线 `#2a3946`。
- 主文字 `#e7eef5`，次级文字 `#a7b7c5`，青色强调 `#18bfdc`。青色按钮使用深色文字 `#07151d`，不能用低对比白字。
- 成功/安全、警告/低安、危险/零安等现有语义继续使用绿、琥珀、红，不把所有状态涂成青色。
- 中文系统无衬线字体，14–16px 正文，28–32px 页标题，18–20px 区域标题，数字启用 tabular-nums。
- 控件圆角 6–8px，容器 8–10px；减少当前大圆角、层层白卡片与阴影。无霓虹光晕、装饰星空、滚动劫持或营销式大标题。
- hover、active、focus-visible、disabled、loading、empty、error 全部使用统一规则；短过渡尊重 prefers-reduced-motion。

## 全站结构

桌面使用约 200–220px 固定左侧导航，品牌在上方，防诈名单/行星资源/星系导航为主入口，账户/设置/退出在下方。右侧内容区以 24–32px 节奏排列，主工作区优先于帮助说明和概览。

现有登录、鉴权、角色权限、访问路径、返回路径保持不变。管理员页不能因为换导航而变得可越权访问。品牌返回首页使用语义化链接并支持键盘。备案号与工信部链接继续全站显示。

参考图为约 1440×1024 桌面目标；需验证 1280、1440、1920 宽度与浏览器缩放。保持当前桌面版的窄屏支持边界，小屏提示同步改为新主题，不在本次改版里暗中新增一套移动端业务流程。表格可在自己的容器内横向滚动，页面本身不得横向溢出。

## 行星资源与计算器

1. 将长期展开的地点选项收进可展开的多选筛选器，默认保留可见标签、当前选择与清除操作；星域→星座→星系的依赖和请求参数不变。展开后的资源选择仍保留图片、分组与按名称搜索。
2. 将核心查询控件集中成紧凑筛选条；帮助说明可收起，不再占据大量首屏空间。不得移除“只选资源”“只选地点”等现有查询方式。
3. 结果表保留全部列、筛选、排序、安全等级与加入状态；模拟图中的相关度排序、记录数量、名称和其他示意内容不是新增需求。
4. 结果区域底部设置稳定的批量操作栏。未选中时明确显示“请先勾选资源”，加入按钮仍可辨认但禁用；选中后显示“加入计算器 · N 项”，使用青色实心按钮、深色文字、48px 高度。选中行有复选标记和淡青背景，不仅依赖颜色。
5. “打开计算器”保持次要按钮，显示现有数量，视觉上与“加入”区分。仍沿用当前加入后打开计算器的行为，不改动去重和保存逻辑。
6. 计算器弹窗、指标、方案管理、批量输入、排序表头及删除状态全部转为同一深色体系，公式、排序规则、价格、阵列数量、方案持久化不变。

## 其他页面覆盖

| 页面 | 必须覆盖的视觉内容 | 不能改变的行为 |
| --- | --- | --- |
| 防诈名单 | 检索、列表、详情、举报表单、上传预览、空/错状态 | 查询/刷新、提交验证、上传、登录限制 |
| 星系导航 | 地图工具条、地图旁信息、路线筛选、路线结果、下拉/提示 | 地图数据、定位/缩放、路线算法与查询条件 |

| 用户设置 | 密码表单、价格表、分类、保存与恢复 | 价格维护和账户操作 |
| 举报管理 | 管理员登录、审核列表、详情与历史对话框 | 管理员校验、批准/拒绝、历史数据 |
| 授权管理 | 筛选、列表、表单、状态、操作确认 | 授权接口、权限、生命周期 |
| 信息中心/页脚 | 信息层级、入口、备案链接 | 原有链接与路由 |

## 实施边界与验收

沿用 React 18、Vite、现有 CSS、lucide-react 与 framer-motion，不迁移框架或新增整套组件库。优先整理既有样式为语义变量，而不是在文件末尾堆积大量冲突覆盖。保留已安装图标库和原品牌/资源图片。

变更仅限前端、测试及本设计文档。业务 API、后端和自动部署配置均不在范围内。测试必须使用已有隔离 mock，不向生产提交举报、修改密码、保存方案或做管理员操作。

先写失败测试再实现。既有 77 项 E2E 必须保持通过，补充主题/布局/操作栏/键盘/滚动覆盖。按页检查真实浏览器截图，参考图与实现同尺寸对比，修正明显差异。视觉验收不能只用构建或 HTTP 200 代替。

在 `codex/ui-dark-console` 独立分支完成；不推送 master，避免触发已开启的自动生产部署。完成本地预览、测试和评审后交给用户确认，再决定合并发布。
