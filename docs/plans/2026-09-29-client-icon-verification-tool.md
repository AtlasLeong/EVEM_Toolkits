# 客户端物品图标校验与映射工具设计

## 背景

客户端离线资源已经提取并解码出候选图片，但目前无法从客户端资源表中可靠地自动反查“资源路径 → 物品 ID”。制造目录和市场页需要稳定的图标映射，错误绑定会比使用统一占位图更难发现。因此采用人工确认、代码消费的安全流程。

## 目标

- 提供仅供开发/管理员使用的本地图标校验页。
- 支持按物品名称、物品 ID、图标 ID、源文件哈希搜索候选图片。
- 允许预览候选图、绑定、撤销绑定，并明确显示来源与校验状态。
- 生成可审查的映射数据；只有人工确认的数据才进入生产资源。
- 制造页优先读取已确认映射，未命中时保持现有 WebP 图标和占位图回退行为。

## 非目标

- 不在普通用户制造页展示 8000+ 候选资源。
- 不在本阶段继续猜测客户端哈希算法并自动写入生产映射。
- 不改变市场采集、制造成本计算或现有商品 ID 语义。

## 方案

### 管理页

新增开发路由 `/dev/icon-verification`（不在普通导航中展示）。页面采用三栏布局：

1. 物品栏：仅列出制造目录/市场目录中尚未确认或存在冲突的物品，支持名称、ID、分类筛选。
2. 候选栏：分页展示解码候选图，支持候选哈希、尺寸、格式和来源目录筛选；缩略图懒加载。
3. 绑定栏：展示当前绑定、候选原图/缩略图、来源哈希、确认时间和撤销操作；冲突时阻止静默覆盖。

绑定操作只生成待审查变更，保存时输出映射 JSON；导入前执行 schema、ID、路径、哈希、尺寸和重复资源校验。

### 数据流

```text
decoded-images-manifest.json
        ↓ (离线生成缩略图索引)
icon-candidates.json
        ↓ (开发管理页人工确认)
current-item-icon-mapping.json
        ↓ (构建前生成受控静态资源)
front-codex/public/images/market-items/*
        ↓
MarketItemIcon → confirmed mapping → legacy allowlist → Package fallback
```

### 映射记录

每条记录包含：

- `itemId`：正整数字符串。
- `iconId`：客户端逻辑图标 ID（可为空，但不能与 `iconPath` 同时为空）。
- `iconPath`：生产资源相对路径或受控静态 URL。
- `sourceHash`：候选源文件 SHA-256。
- `width` / `height` / `format`：构建时校验元数据。
- `status`：`confirmed`、`conflict` 或 `revoked`。
- `confirmedAt`：ISO 时间戳。

生产消费只接受 `status: confirmed`，并拒绝重复 `itemId`、重复 `iconPath`、路径穿越和非白名单格式。

## 制造页接入

在 `getMarketItemIcon` 中先查已确认映射，再查现有 48 个经过测试的 WebP 资源。映射模块保持纯函数，未知 ID 继续返回 `null`；`MarketItemIcon` 的现有失败回退不变。

## 性能与安全

- 管理页只加载候选索引和缩略图，不将原始 982MB 资源打包进前端。
- 生产构建只复制已确认资源；缩略图与原图分离。
- 所有路径在构建时规范化并限制在静态资源根目录内。
- 映射变更可通过 JSON diff 审查，禁止运行时静默覆盖。

## 验证

- 单元测试：索引 schema、映射 schema、冲突/撤销、未知 ID 回退。
- 组件测试：绑定状态、冲突提示、撤销确认、图片加载失败回退。
- E2E：搜索物品 → 选候选 → 绑定 → 保存 → 制造页显示；冲突候选不覆盖已有映射。
- 构建检查：只打包确认资源，检查 bundle 大小和路径穿越。

## 分阶段交付

1. 建立索引/映射 schema 与只读候选预览。
2. 增加绑定、撤销、冲突校验和导出流程。
3. 接入 `MarketItemIcon`，保持旧资源回退。
4. 执行测试与构建，审查映射 diff，再逐步加入已确认客户端图标。
