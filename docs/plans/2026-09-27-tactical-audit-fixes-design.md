# 战术板审查修复设计

用户已批准 2026-09-27 审查建议的本地修复与优化。本轮不推送、合并或部署。

## 边界与方案

- 保留真实 X/Z 等比例投影、安等颜色、组织权限和板间隔离；不重写 Canvas 引擎。
- 海盗板视觉标签可以抽样，鼠标/触摸命中必须查完整星系集合，密集候选不能误报地点；键盘继续有可访问入口。
- 滚轮实时底图补绘与昂贵的卡片布局分开。战争板同屏卡片设置预算，选中目标优先，未展示上报仍可在列表访问；稳定方位，不通过丢数据提速。
- 斥候只开放后端允许的人数上报，不扩张部署权限。
- 幂等请求摘要排除连接租约标识，但每次重试仍检查身份、组织、板与租约；不同业务内容必须冲突。保留旧摘要安全兼容，不能为兼容跳过内容核验。
- 连接租约过期与成员撤权使用不同协议信号。前者可重新入场；后者继续清空敏感信息。
- 海盗板补独立的当前战区星系搜索，选择结果只定位；点击星点仍可预填上报。
- 两板统一缩放手感、关键文字对比与可触达控件。手机保留地图/列表切换，不把地图功能删除。

## 验证

先补失败测试再修复，执行隔离 Django CI 配置、前端单元测试、Playwright 本地 API 夹具、构建和分包预算。覆盖密集地图、持续缩放、对话框关闭焦点、不同角色、断线恢复、390/768/1100/1440 布局。性能数字注明测量层级，不将纯函数耗时称为浏览器帧率。

## 不包含

不改生产数据库，不接触真实上报，不修改 SSH/线上环境，不重构市场/军团/星海见闻。星系导航自身的问题单独处理，本轮仅借鉴其克制的地图视觉规则。
