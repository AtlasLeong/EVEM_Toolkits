# 星图卡片锚点优化设计

## 背景

星图上的舰队、人数上报和战报卡片虽然带有引导线，但在星系附近拥挤时会从星点右侧或左侧开始，用户很难第一眼判断卡片属于哪个星系。现有布局候选顺序包含正上方，但冲突检测会让卡片直接跳到侧边，且“星系名称”保留区的权重过高。

## 目标

- 统一调整舰队、人数上报和战报卡片的锚点规则。
- 默认让卡片在所属星系点的正上方或正下方居中。
- 仅在上下位置与工具栏、其他卡片或星点发生真实冲突时使用左右位置。
- 保留现有引导线、卡片尺寸自适应、拖动和缩放期间的稳定槽位。
- 不改变星系坐标、移动权限或后端数据结构。

## 方案

在 `layoutForceMarkers` 中将候选位置分为三层：

1. 正上方和正下方的居中位置；
2. 上下位置的有限水平微调，用于绕开相邻星点或已放置卡片；
3. 左右位置作为最后的避让策略。

“星系名称”只作为软占位，不再阻止卡片使用上下居中位置；工具栏、其他卡片和星点仍是硬冲突。首个可见位置继续写入 `preferredSlots`，所以滚轮缩放和轮询刷新不会让卡片反复换边。

## 交互与视觉

- 正上方/正下方卡片的中心线与星系点重合。
- 引导线从卡片最近边的中心指向星系点，避免出现贯穿卡片的竖线。
- 密集区域仍自动避让；上下均不可用时，侧边卡片通过引导线明确归属。
- 不新增动画或持续布局计算，保持现有缩放性能。

## 验证

- 单元测试覆盖：默认居中、上下冲突时的避让、左右兜底、槽位稳定性和现有不重叠约束。
- 运行 tactical marker layout 单元测试、战术板 E2E，以及前端构建。
- 在本地预览中检查单星系、密集星系、边缘星系和滚轮缩放四种场景。
