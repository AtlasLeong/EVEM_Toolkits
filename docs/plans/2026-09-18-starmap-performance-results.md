# 星图性能优化验证记录

## 范围

分支 `codex/starmap-performance`，基线 `535034c`。仅修改前端 `TacticalStarMap.jsx`、`TacticalBoard.jsx`，不修改路线 API、算法、数据库或服务器配置，不推送或部署。

实现：画布尺寸变化检查（含纯 DPR 变化监听）、世界坐标视口裁剪、星门绘图层去重、缓存安等颜色、手动输入按帧合并并立即累积相机值、拖动/缩放期间简化细节、静态星图数据一小时内存缓存。后台压缩仍为后续独立工作；本次不宣称首次网络下载变快。

## 测试驱动证据

- 原有 6 项「星系导航」测试基线通过（29.9 秒）；时间戳回退保护在后续专项/全量中覆盖。
- 新渲染测试在旧版出现 4 项预期失败：定位期间宽高赋值由 4 次增至 140 次；近景本应只绘制中心星系却绘制全部 5 个；5 次同帧滚轮预期 4.98x 实得 6.96x；拖动期间仍保留全部光晕。
- 缓存测试旧版有 2 项预期失败：离开 4/6 分钟后四组查询均从 1 次变为 2 次。修改后一小时内复用，超过一小时重新验证，失败数据可在重访时恢复。
- 测试几何修正：画布逻辑尺寸沿用父容器取整值，不把 Canvas 的 CSS content box 与父容器 border box 混淆；滚轮锚点以浏览器实际接收的整数事件坐标验证，保持严格坐标断言。
- 新增性能/边界 8 项全部通过（38.6 秒）；缓存专属 4 项通过（10.8 秒）。

## 可重复绘制采样

运行命令（`front-codex`）：

```text
npm run test:e2e -- tests/e2e/specs/starmap-performance.spec.js --workers=1
```

夹具为固定生成的 5,428 个星系、13,518 条双向星门记录，默认 Chromium/Desktop Chrome 视口 1280×720。它接近线上数据规模，但不是实际星系分布。Canvas 方法包装保留原始调用，报告在 Playwright 附件 `starmap-workload.json` 中，并保留定位截图。

| 指标 | 旧版单 worker | 优化后单 worker |
| --- | ---: | ---: |
| 全景每次星点 arc 调用 | 5,428 | 5,428 |
| 定位期间画布宽高赋值次数 | 122 | 0 |
| 定位结束近景每次星点/光晕 arc 调用 | 10,856 | 30 |
| 定位结束近景每次星门 lineTo 调用 | 13,518 | 30 |
| 定位结束近景名称数 | 15 | 15 |
| 定位过程中绘图 JS 采样中位数 | 6.6 ms | 0.6 ms |
| 定位过程中绘图 JS 采样 p95 | 11.7 ms | 2.4 ms |

解释：减少的是冗余绘制指令，地图数据/HUD 原始星门数仍保留，视口内名称一致。全景本就需要显示所有星点，不宣称全景也减少到 30 个。时序是本机开发构建、带观测包装的一轮采样，动画帧数会因调度改变（61/65 帧）；不等同 GPU 完成时间、真实用户 FPS 或普遍提升倍数。
