# 战术板修复与优化验收

日期：2026-09-27。基线：`41f0157dbf1886b31fa7f73164d14825168f6fa1`。

工作分支：`codex/tactical-audit-fixes`。本轮仅本地修改与验证，没有推送、合并、部署或修改生产数据。

## 已实施的修复

### 地图正确性与交互

- 海盗板鼠标／触摸按完整星系空间索引命中，不再依赖抽样的键盘热区；近距离难以区分的星点先展示地点候选，拖拽不触发上报。
- 两板共享滚轮计算、同帧增量合并、倍率上下限与边界反向规则；按钮步幅统一为 1.25，倍率范围统一为 0.5–16。
- 连续缩放期间约每 80 ms 按实时相机补齐底图，卡片避让留在手势结束后，不等待滚轮停止才显示新区域的星点和星门。
- 卡片、独立关闭按钮、文字和引导线按所属星系锚点补偿。新增测试验证实际位置，不再只验证卡片尺寸；战争板旧实现连续缩放漂移约 43 px，修复后测试误差小于 1 px。
- 搜索选中星系在抽样、布局优先级与高亮中使用同一有效 ID，兼容数字及字符串 ID，不再出现“选中圈有了，名称没了”。
- 保留真实 X/Z 等比例投影、安等颜色及细选中圈；覆盖点击星系、关闭上报、继续缩放与键盘焦点恢复。

### 性能

- 战争板平移使用现有图层变换，不再逐帧重复卡片排版。
- 同屏卡片布局设置 24 行预算，选中对象优先；未展示数量可见，完整数据仍可从列表访问，没有删除上报。
- 复用稳定方位，先检查居中／已记忆位置，减少不必要的 48 候选评分与重复求解。
- 性能数字见下方基准章节；不把纯函数测量描述为浏览器 FPS。

### 上报、连接与权限

- 业务幂等摘要排除 `connection_id`。新请求保存成功但响应丢失时，换连接使用同一请求 ID 重试可正确返回原结果；每次仍验证当前用户、组织、板、成员和租约。
- 过期租约使用 `lease_expired`／WebSocket 4408，与真实撤权 4403 区分。过期后重新入场，恢复前只读；撤权仍清除敏感快照。
- 不自动重放写请求。待发送上报保留原始请求身份，由用户显式重试。
- 斥候只展示服务端允许的星系人数上报，统帅／指挥保留舰队部署管理；人数模式不再携带隐藏的舰船构成字段。

### 页面与移动端

- 海盗板新增独立的当前战区星系搜索，可定位没有目标线索的星系；选择搜索结果不自动提交或打开上报。
- 两板在 1100 px 使用一致的桌面／移动布局断点，手机都有地图／列表入口；战争板保留搜索、选点、详情和上报。
- 地图工作区统一深色浮层与成对的前景／背景变量，外围站点及表单保持原主题；关键侧栏文字测量对比度不低于 4.5:1。
- 修复手机详情返回总览后列表仍隐藏、桌面展开状态切至手机后详情不可见，以及选中舰队跨列表分页时找不到详情。
- 手机海盗搜索与缩放控件错开，补充按钮实际可点击性验证，不只检查元素存在。

| 同屏人数上报总数 | 基线布局 | 修复后布局 | 原／新可排出的名称数 |
| --- | --- | --- | --- |
| 50 | 12.9 ms | 3.1 ms | 9 / 21 |
| 100 | 32.1 ms | 5.3 ms | 3 / 32 |
| 300 | 268.6 ms | 22.4 ms | 0 / 13 |
| 900 | 2122.5 ms | 143.1 ms | 0 / 13 |

最终由主代理在浏览器回归结束后运行仓内 `scripts/benchmark-tactical-layout.mjs`，Node v24.13.1 / Windows x64。输入固定为 1200×700 格点星图，每星一条人数报告，分别平移 0 / 2 / 4 px。

新实现只把预算内最多 24 行交给昂贵卡片布局，完整上报仍保留在列表。900 场景新耗时样本为 137.6 / 143.1 / 159.4 ms，其中名称布局分别占 130.5 / 138.5 / 148.2 ms，剩余瓶颈主要在手势结束后的名称避让。

绝对耗时受本机负载影响：此前与普通 E2E 并行测量的同场景中位数为旧 4019.4 ms、新 179.0 ms。测量不含 React、浏览器绘制与网络，不能据此宣称稳定 60 FPS，也不是两种实现展示同样数量卡片时的算法倍率。

这是开发模式下的按钮触发完整重排测试，包含调度和等待，不是连续滚轮的单帧耗时。该超大场景仍有明显优化空间；本轮未为它宣称流畅帧率，也未把 DOM 数量上限断言当作耗时达标。

## 保留限制与发布注意

1. **旧版幂等收据兼容有限。** 旧数据库仅保存含连接 ID 的不可逆摘要。旧连接精确匹配的重试可安全升级；未知旧连接的历史请求无法证明业务内容一致，仍安全返回 409。不能靠绕过校验或换请求 ID 自动重报解决不确定结果。
2. 大规模场景的手势结束布局仍有成本，后续可以继续优化名称碰撞索引；本轮不重写 Canvas 引擎。
3. 尚未做真实手机硬件、生产 MySQL 多人并发负载或线上跨代理网络验收。现有隔离测试不能代替这些发布前验证，也不是全站安全认证。
4. 星系导航模块本身未改动；仅借鉴其克制的视觉层级，没有复制其非等比例投影或手机隐藏地图的做法。
5. 发布需要前后端配套更新，以便客户端识别新的租约恢复码。本轮未上线。
