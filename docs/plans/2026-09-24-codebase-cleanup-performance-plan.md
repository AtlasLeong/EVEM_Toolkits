# 代码仓清理与性能优化实施计划

## 范围

本轮只处理已确认的五项，不修改生产安全配置、硬编码凭据和旧采集脚本：

1. 移除未被 Django 应用引用且包含 NUL 字节的根目录重复模型文件。
2. 移除前端未使用的 `dayjs`、`recharts` 依赖及空的手工分包配置。
3. 移除仓库内无引用、未参与当前构建或部署的 `frontend-v2` 目录。
4. 优化后端高频全量查询/N+1：战术板坐标接口复用缓存/只取公开字段，Bazaar 使用数据库聚合，Fraud 报告证据批量查询，行星资源列表保持数据库侧排序和切片。
5. 将战术协作 HTTP 兜底从固定 2 秒轮询改为可见性自适应和退避；实时连接恢复时立即刷新，页面隐藏时暂停高频刷新。

## 不变式

- 当前 `front-codex` 路由和 API 响应字段不变。
- WebSocket/HTTP 两条协作路径都保留；命令提交仍走 HTTP。
- 只删除已验证无引用的文件/依赖，Git 提交可完整恢复。
- 不新增数据库迁移；查询优化必须兼容现有 MySQL/SQLite 测试环境。

## 测试先行

- 增加/调整单元测试，验证依赖清理后的构建和 bundle 清单、HTTP 轮询的可见性与退避、坐标接口缓存命中、Bazaar 聚合/Fraud 批量查询的查询数边界。
- 在修改前记录基线：`python -m compileall backend`（当前因 NUL 文件失败）、`node --test tests/unit/*.test.mjs`、星图性能 Playwright、`npm run build`。
- 修改后运行全套前端单元、星图性能、战术 E2E、生产构建/bundle budget，以及后端部署/战术测试。

## 实施顺序

1. 先提交测试和依赖/死文件清理，确认工作树无意外文件。
2. 实现后端查询优化并用 QuerySet/响应测试验证行为与查询量。
3. 实现前端 HTTP 兜底调度器（`visibilitychange`、指数退避、WS 恢复刷新），补齐 hook 测试。
4. 运行回归和性能基线，记录前后对比；如任何行为回归，按提交粒度回滚对应阶段。

## 验收指标

- `python -m compileall -q backend` 成功。
- `depcheck` 不再报告 `dayjs`/`recharts`，构建不产生空 `charts-vendor` chunk。
- `frontend-v2`、根目录重复模型文件均不再出现在发布包和当前部署路径。
- 星图性能用例保持通过；HTTP 兜底在隐藏页面不发请求，失败时按退避而非固定 2 秒重试。
- 后端现有测试全部通过，关键列表接口不再出现已知 N+1。
