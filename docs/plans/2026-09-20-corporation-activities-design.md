# 军团主要活动与表单精修设计

用户已确认本方案。工作范围仅 `codex/community-corp` 本地版本，不合并、推送、部署或连接线上数据库。

## 目标

- 修复 textarea 继承全局 `.text-input { height: 44px }` 导致裁切；介绍约 180px，支持/要求约 140px，补充约 110px。桌面字段间距 20px、移动端 16px，标签间距 8px，分组约 24px。仅军团编辑页作用域。
- 第三编辑页改为“主要活动”，使用长期军团玩法介绍，不再用单次活动标题、日期和集结点建模。
- 活动方向以“主权生产”“海盗作战”替代新用户可选的“舰队作战”，其余五个内置选项保留。
- 添加最多 5 个、各最多 12 个 Unicode 码点的自定义标签，支持添加、删除、重复反馈。新文本继续走原有审核。
- 公共卡片、详情、审核和第三海报模板同步；8 款背景和 4 款默认横图不变。

## 数据合同

Revision JSON 新增 `activity_description`（选填，1500 字）和 `custom_activity_tags`（数组）。无需数据库迁移。

内置键：`sovereignty_production`, `pirate_combat`, `pve`, `industry`, `exploration`, `mining`, `training`。旧 `pvp` 仅允许沿用同一草稿原有值，不可新添加；仍可通过旧筛选 URL 查询，不映射为新分类。

自定义标签 trim 后验证长度，拒绝空项、控制字符/换行、重复、与内置/旧标签同名；NFKC + Unicode casefold 比较键用于判重。服务器拒绝错误输入，不静默截断；读取异常历史值时安全归一化，不修改快照。标签不进入 `activity_keys`，本次不增加自定义标签搜索。

四个 `event_*` 旧字段原文保留。只读返回 `activity_content_kind: overview | legacy_event`，以原始 JSON 是否含 `activity_description` 判定。新默认是 overview，历史缺字段是 legacy_event。新字段明确清空不回退旧数据。编辑旧资料可读查看旧活动，保存新表单时采用 overview；审核可查看完整新旧内容。旧已发布快照保留旧活动显示，直到新版本获批。

## 界面

主要活动页：简短说明、大号活动介绍输入框、示例提示（主权战、反收割、小队游猎、生产协作）；旧活动如存在在折叠只读区展示。活动标签仍在原活动方向区，新增标签输入框+添加按钮，IME Enter 不误提交，删除按钮可访问，数量提示与局部错误反馈。

卡片最多展示 4 个标签加 `+N`，详情显示全部。海报第三模板保留内部 ID `event`，显示名“主要活动”；新版使用军团名称、一般驻地、活跃时间、活动介绍、有限标签摘要；旧资料显式兼容。未审核水印不变。

## 验证与边界

后端验证限额、历史兼容、审核隔离、筛选；前端单元验证标签与海报；真实浏览器验证增删/保存回显、只读、键盘/IME、桌面手机高度与布局、详情和海报。同步本地沙盒合同，避免演示与真实 API 分叉。保留现有用户文件与本地测试输出。
