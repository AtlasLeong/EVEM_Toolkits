# 寻路准确性与性能优化设计

2026-09-18 用户已确认：保留现有加权成本、成本相同时少跳；采用精确搜索、空间索引和静态缓存，并在实施后深度审查。本轮独立分支，不合并、不推送、不部署。

## 目标和边界

- 土路成本 0，安全诱导成本为实际光年距离，涉及负安的诱导为距离乘 1.5；排序目标为 `(累计成本, 跳数)`。
- 状态是 `(system_id, passed_high_low)`，标志在 high/low 到 negative 时永久置真。所有标签、前驱和边类型按完整状态保存。
- 使用 Dijkstra，堆中有唯一序号、跳过过期标签；去除错误的直线启发式和非累计的 +1000。零成本路线自然优先，不再先运行一次错误的全土路 A*。
- 开启土路且存在门时：safe→safe 免费；negative→safe 仅标志 false 时免费；negative→negative 仅实际距离严格大于 9 光年时免费；safe→negative 不免费。其余移动必须满足 `0 < distance <= max_distance`，门不能豁免诱导射程。
- 保留高安候选过滤的数据库 `Round(security_status, 1) < 0.5` 口径；保留 security=0 属 low、星门双向补全以及新八端点限制。不扩展新八中间节点规则。
- 不改前端、响应结构、生产依赖、数据库结构；不新增路线结果缓存、Redis、后台线程或部署动作。

## 组件与数据流

1. `A_Star.py` 保留旧入口兼容，并提供独立于 Django 的 `RouteGraph`。构造一次 ID 字典、去重门邻接和 cKDTree。通过 `find_route(start, goal, radius, allow_dirt, allowed_ids=None)` 返回现有 `(Galaxy, move_type)` 列表或 None。
2. 索引查询采用精确模式 eps=0/workers=1，候选半径保守覆盖浮点边界，再以原始距离严格复核。独立测试比较全扫描邻居集合，不能因索引漏点或放宽范围改变合法性。请求内复用相同星系的几何邻居。
3. `routing_data.py` 加载静态数据并发布一个只读快照：完整端点元数据、候选图、SQL 计算的非高安集合。每次请求仅持有一个版本。
4. worker 内缓存默认 TTL 300 秒、锁保护单次构建、刷新完毕后原子替换。失败不缓存为无路径，返回 503，短暂退避避免连续打库。快照无可变搜索状态。
5. 元数据异常（例如重复中文端点名、参与寻路的非有限坐标）不静默生成可能错误的路线，记录服务端原因并返回通用 503；不泄漏数据库错误。缺失名字/非法非有限或非正射程返回 400，不擅自加服务端 20 光年上限。
6. API 保留成功数组、错误 `error` 字段、不可达 404、起终点相同空数组。新八拒绝优先于候选过滤，使用同一快照元数据。

缓存是最终一致而非即时同步。TTL 后重新加载；完整静态数据导入后由运维受控重启所有 worker 以即时刷新。没有数据版本列，无法保证外部非原子导入期间多张表始终一致，不声称此问题已解决。

## 备选方案

- 仅补旧 A*：不足以解决状态合并和不可采纳启发式，拒绝。
- 全路线/全半径预计算或共享缓存：复杂度和内存过高，本轮不做。
- 精确搜索 + 全扫描：作为对照实现，不作为默认性能路径。

## 验证与验收

- 红绿回归：同分、超射程、零成本捷径、双状态、全土路少跳、零成本环、不可达、相同端点、0/9/射程边界、所有通行矩阵。
- 独立小图穷举或 Bellman-Ford oracle（不得调用生产边分类）对比 `(cost,hops)`；固定随机种子，输入顺序变化结果稳定。
- cKDTree 与原始全扫描半径集合差分，重复坐标/精确边界/大半径覆盖。
- 隔离 SQLite 的实际 ORM/API 测试；热缓存 0 次星图 SQL、过期重载、并发单次构建、失败退避、503、快照不混用；MySQL ROUND 与 SQLite 的差异明确记录，SQL 表达式不变。
- 将 TacticalBoard 和 NumPy/SciPy 测试依赖接入隔离 CI，绝不导入生产 settings 或 .env。
- 可重复基准报告索引构建、邻居查询、完整冷/热路线和稀疏/密集/不可达样本。精确对照与旧算法分别报告，不拿错误旧路线当正确性基准，不承诺未经测量的线上提速。
- 按规格审查后再代码质量审查，处理重要发现并复测。保留分支和报告供后续发布决定。
