# 海盗情报板地图优先布局设计

日期：2026-09-24
范围：本地预览，不推送、不部署。用户对现有两栏页面提出布局反馈，并补充当前时段目标提示。

## 目标

海盗板与战争沙盘板使用一致的全幅星图舞台、紧凑命令条和浮动操作层；切换板型时主内容区不再从沉浸式地图跳为白底两栏。继续复用板目录、服务端权限投影和海盗板独立 API，不合并战争/海盗业务状态。

## 选择与取舍

选择“统一视觉壳，保留两种地图组件”：海盗板复用战争板的尺寸、位置与控件规格，地图仍由 `PirateIntelMap` 绘制。完全重构成通用地图组件会扩大对成熟战争板的回归范围；只用 CSS 覆盖旧两栏无法解决详情流、搜索和板切换跳变。

## 桌面布局

- 星图铺满战术主舞台。命令条覆盖顶端，左侧为板名/组织，右侧为成员和上报操作；板切换器仍在页面统一位置。
- 地图上方显示轻量计数：未撤下目标、当前时段可能活跃数、覆盖星域数。只有管理者可调整范围。
- 左侧浮动搜索框搜索角色名、精确船型、地点；目标列表可独立收起，输入搜索词会自动展开结果，星图不缩放。修复现有输入框的内外双边框。
- 地图目标标记以紧凑的“角色名 · 船型”卡片靠近星系/星座锚点；同位置或密集位置聚合，避免长期遮住星系名。点卡片/搜索结果显示右侧浮动详情，保留目击历史、上报者和撤下入口。
- “当前时段可能活跃”浮动面板默认只展示前几条；目标必须有明确的每日 UTC 活跃时段，最新有效目击不超过 48 小时，且当前 UTC 落在时段内。跨午夜正确计算；展示“线索推测，非实时位置”提示。点击候选定位地图并打开详情。斥候仅基于服务端返回的本人记录计算。
- 搜索、详情和当前时段面板在窄桌面视口可互相让位；地图缩放、拖拽不因浮层重排失去当前视角。

## 手机布局

保持列表/搜索先于地图的可访问顺序，目标详情紧随列表，星图按需展开和加载。平板宽度也采用此顺序，避免左右浮层把地图挤成窄缝；手机星图的目标卡须避开换行图例。所有操作控件满足可触达尺寸，不能让浮层遮住缩放控件。

## 数据、异常与验证

不增加后端读权限或写接口。活跃提示只在已过滤的 `snapshot.sightings` 中计算，不向斥候暴露全组织目标数或其他上报者。无明确时段、已撤下、过期、范围外线索分别明确呈现，不以“当前在线”措辞误导。保留 10 秒超时、低频 HTTP 刷新和手动刷新；地图失败时操作和目标搜索仍可用。

测试先覆盖跨午夜时段、边界、过期/撤下和可见数据；再覆盖桌面满屏地图、浮动搜索和详情、卡片定位、板型切换无布局跳变、手机抽屉与地图延迟加载。构建和现有战术测试全通过后，在本地浏览器核对桌面及手机视觉，不推送上线。
