# EVEM Toolkit UI 精修设计

## 目标

在现有 EVEM Toolkit 功能和暖白视觉基础上完成一次系统化精修：让桌面端更克制、清晰、有层次，同时让登录、反馈、行星资源、星系导航在手机宽度下可用，而不是只显示“请使用电脑”。本轮不改 API、业务流程、颜色语义或数据结构，不上线。

## 设计方向

采用“暖白编辑台 + 炭黑操作 + 陶土强调”的轻量控制台风格：

- 背景使用低对比暖白，内容表面使用纯白；避免大面积灰色块。
- 主操作保持炭黑，陶土色只用于活动态、焦点、危险/提示边界和少量品牌锚点。
- 卡片减少厚重阴影，改为细边框、轻微浮层和明确的标题/正文层级。
- 保留左侧导航的信息架构；桌面宽度适度收窄内容最大宽度，移动端改为顶部品牌栏 + 横向滚动导航。
- 页面标题、分区标题、辅助说明建立稳定字号与行高比例；数字数据采用等宽数字特性。

## 响应式策略

- `>= 1180px`：固定侧栏、内容区保留舒适边距，工具栏使用多列布局。
- `768px–1179px`：侧栏压缩为图标/标签可切换形态，卡片与表单改为两列或单列。
- `< 768px`：移除桌面遮罩；顶部品牌栏固定在内容上方，导航可横向滚动；所有表单和按钮触控高度至少 44px。
- `< 560px`：行星筛选改为纵向折叠块，星图控制项纵向排列；反馈和登录表单单列，附件/分页不产生横向溢出。
- 星图仍使用深色画布，但在移动端将搜索、定位、重置和路径条件顺序化为可滚动控制区，保证画布不被挤压。

## 组件边界

- `styles.css`：全局 Token、层级、断点和通用响应式规则。
- `AppShell.jsx`：移动端导航语义、品牌栏、菜单按钮及桌面/移动两套导航状态。
- `Primitives.jsx`：页面标题、面板、空状态、按钮的稳定结构，避免各页面重复视觉规则。
- `Login.jsx` / `Feedback.jsx` / `Planetary.jsx` / `TacticalBoard.jsx`：只在需要时增加语义 class 或移动端结构，不重写业务状态。
- `tests/e2e`：增加移动 viewport 的壳层、登录、反馈、行星、星图回归；保留桌面既有断言。

## 验收标准

- 桌面 1280、1440、1920 宽度没有横向溢出，侧栏与内容不重叠。
- 移动 390、768 宽度：登录和反馈可完整操作；行星筛选可展开/收起；星图可查看、搜索和触发路径计算。
- 焦点可见、按钮触控区域不小于 44px，导航有可访问名称。
- 现有业务 E2E 全部通过；新增移动回归通过；生产构建通过。
- 不改变 API 请求、响应、认证、备案页脚、排序和已有错误处理。
