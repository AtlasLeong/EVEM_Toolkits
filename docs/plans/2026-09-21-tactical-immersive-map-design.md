# 战术板沉浸式真实星图设计

日期：2026-09-21。状态：用户已确认采用“地图主视觉＋浮层面板”方向，准备在 `codex/tactical-collaboration` 独立工作树实施。

## 目标

让战术板首先是一张可读、可操作的星图，地图铺满主工作区；统计、筛选、上报、部署详情和人员管理以悬浮层叠加，不再使用固定左右两栏压缩地图。正式数据源使用现有 `TacticalBoard` 的星系、星门、星座、星域静态表；本地演习仍可使用独立库，但应优先从真实静态表读取，缺少数据时明确显示“未加载真实星图”，不能把虚构演习点位伪装成真实宇宙。

## 界面层级

1. 地图画布是底层主区域，桌面端至少占页面可视高度的 70%，随窗口尺寸增长；暗色星图背景、真实星门连线、星系名称、安全系数和敌我部署标记保持高对比度。
2. 顶部浮层包含组织名称、在线人数、同步状态、战区范围、视图筛选和“快速上报”。浮层有半透明暖白表面、轻微阴影和毛玻璃效果，但不遮挡地图中心。
3. 左侧浮层只放地图工具和图层控制：敌方/己方/全部、搜索星系、缩放/适配、边界出口。它默认窄化，展开不改变地图尺寸。
4. 右侧情报抽屉默认窄宽，可收起；选中部署或打开待核对情报时展开。抽屉内容分为部署、情报、成员三个标签，不再永久占用布局列。
5. 地图底部只保留图例、当前范围和操作提示，避免重复标题和统计卡片。
6. 手机端不下载地图图形，保留列表、搜索、快速上报、详情和“星系导航”入口；浮层改为全宽底部抽屉，触控目标不小于 44px。

## 数据策略

- `GET /api/tactical/organizations/:id/map/` 继续由服务端按组织范围裁剪真实静态星图，返回系统坐标、中文名、星座/星域、安全系数、星门边界出口。前端不得自行补全全宇宙数据。
- 真实静态表为空或局部演习库不含真实数据时，响应增加明确的数据状态字段；演习夹具可保留，但名称/标签必须显示为“本地演习数据”。
- 战术部署和报告仍按当前角色服务端过滤，叠加到静态星图上；地图缓存只缓存公开几何，不缓存私密军情。
- 对真实数据做归一化投影：优先使用已有 `x/y`，缺失坐标时在服务端排除并显示数据警告，不把空坐标强行投到原点。

## 交互与安全

- 地图拖拽、缩放与部署拖动保持独立命中目标；浮层点击不穿透到地图。
- 面板收起、筛选和适配视图只改变本地 UI 状态，不改变组织共享战区范围；修改共享范围仍走已有版本控制命令。
- 真实数据加载失败时保留已授权军情列表，提示静态星图不可用；不以空图覆盖已有军情，也不展示隐藏阵营统计。
- 战术权限、WebSocket 连接、幂等和版本冲突协议不变。

## 验收

- 桌面截图中地图主区域明显大于当前版本，右侧面板悬浮且可收起，地图中心不被遮挡。
- 真实星图响应包含真实系统/星门字段；本地演习数据状态可辨识，不出现虚构星系名称冒充生产数据。
- 桌面、手机、统帅/斥候权限、上报、移动、筛选和旧 `/starmap` 回归均通过。
- 现有 211 项回归、战术板专项、前端构建和后端测试全部保持通过；新增失败测试先于实现。
